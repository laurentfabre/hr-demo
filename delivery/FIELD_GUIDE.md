# Field guide / Guide terrain

## Choose the buying decision / Choisir la decision d'achat

| Story | Buyer and trigger | Decision | Measurable evaluation |
|---|---|---|---|
| Capacity / Capacite | CFO, CHRO, COO; committed delivery exceeds capacity | Hire/redeploy budget tradeoff | Reconciled gap, agreed cost/effect assumptions, reviewed action readback |
| Group / Groupe | CHRO, CFO, data platform; acquisition or reorganization | Common group definitions with local continuity | Employee/contractor bridge, FX, fiscal calendar and effective-dated rollup |
| Self-service / Libre-service | CIO, CHRO, security; HR depends on data specialists | Governed tools in the existing agent interface | Two authenticated scopes, cited policy, source availability, latency and maintenance effort |

These are editorial account hypotheses informed by public workforce cases, not
measured Enterprise/Global adoption rankings. DXC and LA County support particular
architecture/value patterns; neither proves the proposed acquisition story or
predicts the customer's outcome. The app links to the primary published sources.

## Five-minute executive path / Parcours de cinq minutes

1. 0:00-0:45: confirm the buyer's decision and one measurable baseline.
   Confirmer la decision et une mesure de depart.
2. 0:45-1:30: select the entity/month; explain the capacity or reconciliation gap.
   Selectionner le perimetre et expliquer l'ecart.
3. 1:30-2:30: ingest the demand change or inspect the group-definition bridge.
   Integrer la demande ou rapprocher les definitions.
4. 2:30-3:45: inspect the source revision and explanation; review an option.
   Examiner la revision, la reponse et une option.
5. 3:45-5:00: show the value range and agree the next decision.
   Montrer la fourchette de valeur et convenir de la prochaine decision.

For ten minutes, add source rejection/recovery and an external-tool read. For
twenty minutes, add the actual HQ/local identity proof, operating responsibilities
and a jointly defined evaluation plan. Keep the live/recorded mode visible.

## Discovery / Decouverte

- What business event makes this urgent? Quel evenement rend ce besoin urgent ?
- Which data is missing, versus already available? Quelle donnee manque vraiment ?
- Which source/metric definitions disagree? Quelles definitions divergent ?
- Which interface must remain? Quelle interface doit etre conservee ?
- What is the current cost and maintenance effort? Quels sont le cout et l'effort actuels ?
- Who owns the budget, metric, source, access and operating workload?
  Qui porte le budget, l'indicateur, la source, les droits et l'exploitation ?
- What result would justify moving forward? Quel resultat justifierait la suite ?

## Objections / Objections

| Concern | Evidence-based response |
|---|---|
| Our HR suite already reports this / Notre SIRH le fait | Keep the suite when one source and standard definitions suffice. Demonstrate the incremental cross-system or operational requirement before adding a platform. |
| We already have BI / Nous avons deja la BI | Compare the same dataset/metric. Test availability of missing source data, shared definitions, permissions and action readback rather than aesthetic differences. |
| We built MCP / Nous avons construit un MCP | Retain the working tool if it meets the need. Measure maintenance, cross-source semantics, rights and cost on the same bounded case. |
| We use Dust / Nous utilisons Dust | Preserve the chosen interface. This release simulates Dust/GCP; the authenticated HTTP contract is real. Actual tenant compatibility must be validated before any claim of customer integration. |
| What about run effort / Et l'exploitation ? | Walk one new table, a failed batch, a metric change and an access update. Name the owner and record the actual minutes; do not promise zero engineering. |
| Is the ROI real / Le ROI est-il reel ? | All demo benefits are modeled. Replace estimates with the customer's baseline, show low/high realization and delay, and separate staff capacity from cash. |
| Is it globally compliant / Conformite mondiale ? | Show actual execution location and assigned access. Country filters and synthetic policy passages do not prove residency, employment-law compliance or source permission propagation. |
| Can another SA run it / Est-ce reutilisable ? | Use the versioned package, explicit target configuration, preflight and reset. Report the clean-package execution evidence and any remaining manual prerequisite. |

## Evaluation plan / Plan d'evaluation

Fill these fields together; defaults are proposals, not commitments.

| Item | Agreement to record |
|---|---|
| Decision / Decision | What investment or architecture decision will the result inform? |
| Scope / Perimetre | One source, one entity, one month, one metric, two identity scopes |
| Expected result / Resultat | Baseline/reference calculation and tolerance approved by the metric owner |
| Access / Acces | Allowed/denied identity matrix, small-cohort rule and permitted export |
| Performance / Performance | p50/p95 latency and concurrency agreed for the actual workload |
| Economics / Economie | Setup, platform, maintenance, benefit attribution, delay, realization range |
| Operations / Exploitation | New-table and recovery tasks, owner and measured effort |
| Authority / Autorite | Sponsor, budget owner, data authority and evaluation owner |
| Decision date / Echeance | Date and explicit go/no-go criteria |

## Expansion / Extension

Land one entity with reconciled outcomes. Add a second entity only after its local
data/rights validation. Expand country by country or domain by domain using the
same definitions and measured operating model. Record incremental workload and
cost; a broad platform ambition is not an approved expansion commitment.
